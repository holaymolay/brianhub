Help

API overview

This draft documents the current BrianHub API as implemented today.
Base URL
https://brianhub.com
Current workspace
<workspace-id>
Production uses session-cookie auth for product routes. Bearer and service-account auth are not active yet.

Public routes

  • GET /health
  • GET /auth/me
  • POST /auth/login
  • POST /auth/logout
  • POST /auth/invite/accept
All other product routes require an authenticated actor when auth is enabled.

Tasks and sections

My Tasks sections are represented by group_label on each task. There is no dedicated sections endpoint yet.
  • Use POST /tasks to create a task.
  • Use PATCH /tasks/:id to update task fields.
  • Set group_label to place a task into a section.
  • Set group_label to null to remove a task from a section.
Do not model sections as parent tasks with subtasks. Subtasks are hierarchy, not grouping.

Shopping lists

Shopping lists and shopping items are first-class API resources. Use these routes instead of trying to encode shopping state into tasks.
  • GET /shopping-lists?workspace_id=<uuid> lists shopping lists for a workspace.
  • POST /shopping-lists creates a shopping list.
  • PATCH /shopping-lists/:id updates a list name or archive state.
  • DELETE /shopping-lists/:id deletes a list.
  • GET /shopping-items?workspace_id=<uuid> or GET /shopping-items?list_id=<uuid> lists items.
  • POST /shopping-items adds either one item with name or many items with items.
  • PATCH /shopping-items/:id updates name, is_checked, or sort_order.
  • DELETE /shopping-items/:id deletes an item.
